# 翻译错误修复表

本文档扩展 SKILL.md 中的错误修复表，提供更详细的错误场景、诊断方法和修复步骤。当 verify.sh 或 check_translation_lock.py 报错时，可在此表中查找对应错误码。

| 错误码/症状 | 诊断方法 | 修复步骤 |
|-------------|----------|----------|
| `CODEBLOCK CONTENT MISMATCH` | 对比英文源文件与中文文件的代码块数量和内容 | 从英文源文件原样复制代码块，仅翻译纯注释行 |
| `PLACEHOLDER MISMATCH` | 用正则 `\$\{?\w+\}?` 和 `\{\{.*?\}\}` 扫描两份文件 | 从英文源文件复制遗漏的占位符 |
| `YAML KEY MISMATCH` | 提取两份文件的 YAML frontmatter，对比 key 集合 | 复制英文 YAML 头部，仅翻译 value 中的自然语言 |
| `SYSTEM-REMINDER TAG MISMATCH` | 统计 `<system-reminder>` 和 `</system-reminder>` 的数量 | 对比英文源文件，补齐缺失的标签 |
| 转义反引号被展开 | 搜索连续三个反引号，检查是否应为转义形式 | 用 StrReplace 将 ``` 改回 `\`\`\`` |
| 术语不一致 | 搜索术语表中的每个术语，检查是否有变体写法 | 统一为术语表中的标准写法 |
| 链接被翻译 | 搜索 `](` 和 `](#`，检查 URL 和锚点是否被修改 | 从英文源文件复制链接部分 |
| HTML 注释头标记缺失 | 检查文件开头是否有 `<!-- 翻译已完成` 或 `<!-- TODO: 翻译待完成` | 根据翻译状态添加对应标记 |
| 锁版校验失败 | 运行 `scripts/check_translation_lock.py <file>` 查看具体报错 | 按脚本输出的具体项逐条修复 |
| 章节结构被改动 | 对比英文和中文文件的标题列表（`grep "^#"` 两份文件） | 恢复英文原始章节结构，仅修改标题文字 |

## 失败恢复策略

- **来源冲突**：以官方站点与原始 PDF 为准，在文档中标注冲突点
- **页码识别异常**：先按标题分段，再补页码映射
- **术语口径冲突**：列出候选译法，选定锁版口径并在术语变更记录中说明原因
