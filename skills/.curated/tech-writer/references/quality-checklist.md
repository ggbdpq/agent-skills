# tech-writer 质量验收清单

本清单用于 tech-writer 的 Step 5 质量验证阶段。逐条检查，全部通过方可输出终稿。未通过项需回到对应步骤修复后重新检查。

## 结构完整性

- [ ] H1 唯一，全文仅一个 `#` 标题
- [ ] 标题无编号前缀（不出现 `## 1 引言` 格式）
- [ ] 标题层级递进，无跳级（`##` 后只接 `###` 或同级 `##`）
- [ ] 引言包含覆盖范围、读者预期、可运行的最小示例
- [ ] 包含「读者收益」章节，使用动词短语（如「能配置 X」「能排查 Y」）
- [ ] 包含「适用范围与版本说明」章节，附核验命令
- [ ] 包含「常见问题与排查」章节
- [ ] 文末元信息使用斜体脚注，不使用 blockquote

## 表格与示例

- [ ] 每个表格前有引导段落（解释表格用途和阅读方式）
- [ ] 每个命令示例有上下文说明（为什么运行、预期结果）
- [ ] 代码块标注语言（bash、json、typescript 等）
- [ ] 代码中占位符使用 `<placeholder>` 格式并在代码块后说明

## 语言质量

- [ ] 无 AI 填充语（「此外」「值得注意的是」「需要强调的是」）
- [ ] 无口语化表达（「速查」「慎用」「干货」「一文搞懂」）
- [ ] 无元叙述（「作为 AI」「我来帮你」）
- [ ] 无感叹号
- [ ] 无同义循环（同一概念在连续段落用不同说法）
- [ ] 无二元反衬式套话
- [ ] 无过度形容词（「强大的」「优雅的」「令人印象深刻的」）
- [ ] 短句优先：无标点不超过 40 字，有逗号不超过 100 字

## 排版规范

- [ ] 中英文之间有半角空格
- [ ] 中文与数字之间有半角空格
- [ ] 全文无破折号字符（`—` `–` `--`）
- [ ] 全角标点用于中文语境，半角标点用于代码上下文
- [ ] 专有名词保留原始大小写（GitHub、macOS、JavaScript）

## 准确性与可验证性

- [ ] 版本相关内容附核验命令
- [ ] 功能清单注明「以本机实际输出为准」
- [ ] 个性化内容（如 Skills 列表）有免责提示
- [ ] 无武断断言（「所有版本都支持」「一定能解决」）
- [ ] 配置示例可运行，或注明前置条件

## 工程留痕质量

- [ ] 背景说明包含真实触发原因或阻断链
- [ ] 变更内容能对应到文件、模块或配置
- [ ] 生效边界明确到目录、平台、命令或使用场景
- [ ] 写明未改事项，避免 review 人误解为遗漏
- [ ] 验收方式包含可执行命令或可复查的人工检查点
- [ ] 回滚方式明确到文件、配置或提交范围
- [ ] 局部试点没有被表述成全局生效规则
- [ ] 如果引用 git commit，包含 commit 标题和核心改动范围

## 失败处理

如果某项无法满足（例如文档类型不适用「读者收益」章节），在该项后标注跳过原因。跳过不等于通过，需在输出时注明。
