# 常见问题与故障排查

本文档列出 tech-writer 执行过程中常见的输出问题及修复方法。当 Step 5 质量验证未通过时，可在此表中查找对应症状并按修复步骤处理。

## 排查表

以下表格按"症状、原因、修复"三列组织，覆盖最常见的质量问题。

| 症状 | 原因 | 修复 |
|------|------|------|
| 输出中出现 `—` 或 `–` 字符 | 源文档含破折号，润色时未替换 | 全文搜索 `—`、`–`、`--`，替换为逗号、括号或分句 |
| 标题带编号前缀（如 `## 1 引言`） | 源文档使用手动编号 | 删除编号前缀，保留语义化标题 |
| 标题层级跳级（`##` 后直接出现 `####`） | 结构改写时遗漏中间层级 | 检查标题层级递进，补齐缺失层级 |
| 表格前无引导段落 | 直接复制源文档表格 | 在表格前添加一句说明表格用途和阅读方式的段落 |
| 命令示例无上下文 | 源文档仅罗列命令 | 每条命令前补充用途说明和适用场景 |
| 出现「此外」「值得注意的是」 | AI 填充语未清除 | 删除段首填充语，直接进入内容 |
| 出现「速查」「慎用」「干货」 | 口语化表达未替换 | 替换为客观技术写作表达 |
| 出现「作为 AI」「我来帮你」 | 元叙述泄露 | 删除整句或改为客观表述 |
| 版本声明无核验命令 | 武断断言未修正 | 补充可执行的核验命令（如 `xxx --version`） |
| 中英文之间无空格 | 排版规范未执行 | 在中文与英文/数字之间插入半角空格 |
| 同一概念用不同说法 | 同义循环未统一 | 选定一个术语全文统一使用 |
| 输出被截断 | 文档过长导致输出不完整 | 分段输出或确认输出完整性 |
| 代码块未标注语言 | 源文档代码块缺少语言标识 | 为每个代码块添加语言标注（bash、json、typescript 等） |
| 文末使用 blockquote 放版本信息 | 错误的元信息格式 | 改为斜体脚注格式：`*本文基于 X 版本。*` |
| 功能清单无免责提示 | 遗漏「以本机实际输出为准」 | 在清单处补充免责说明和核验路径 |
| 出现感叹号 | 技术文档中不应使用感叹号 | 将感叹号改为句号，调整语气为陈述式 |
| 出现「不仅仅是……而是……」 | AI 写作常见句式未清除 | 删除该结构，直接陈述事实 |
| 过度使用粗体 | 机械强调短语 | 仅保留必要强调，删除装饰性粗体 |

## 未覆盖问题的处理

如果遇到本表未覆盖的问题，请按以下顺序排查：

1. 查阅 [references/anti-patterns.md](anti-patterns.md) 逐条对照
2. 查阅 [references/formatting-rules.md](formatting-rules.md) 逐条对照
3. 回到 SKILL.md 的 Step 3（语言润色）和 Step 4（排版规范化）重新执行
