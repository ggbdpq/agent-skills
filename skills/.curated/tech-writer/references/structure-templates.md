# 中文技术文档结构模板

本文档提供常见技术文档类型的结构骨架与撰写规范。各模板采用祈使语气，以简体中文书写。

---

## 工具参考手册模板

适用于 CLI 工具、API、类库等参考型文档。

```markdown
# [工具名称] 参考手册

## 引言
<!-- 说明文档覆盖范围、目标读者技能水平、提供一段 5 行内的快速上手代码 -->

## 读者收益
<!-- 读完能做什么，3–5 个具体要点，使用动词短语 -->

## 适用范围与版本说明
<!-- 版本基准、与其他版本/分支的差异声明、可执行的核验命令 -->

## 基本语法
<!-- 核心用法、必选/可选参数一览 -->

## 选项详解
<!-- 按功能域分组（如：输入输出、调试、配置），每组有 1–2 段解释 + 参数表格 -->

## 用法示例
<!-- 按场景分组（如：本地开发、CI、集成），每个示例附带上下文说明 -->

## 常见问题与排查
<!-- 使用「症状→原因→解决步骤」三段式格式 -->

## 术语表
<!-- 三列表格：中文 | 英文 | 简要解释 -->
```

### 撰写要点

| 章节 | 包含 | 避免 |
|------|------|------|
| 引言 | 一句话概括用途；目标读者；可运行的最小示例 | 冗长背景、与读者无关的动机 |
| 读者收益 | 可检验的结果（如「能配置 X」「能排查 Y」） | 泛泛的「掌握」「了解」 |
| 选项详解 | 参数含义、默认值、互斥/依赖关系 | 逐条罗列而无分类和说明 |
| 常见问题 | 真实错误信息、明确步骤、链接到相关章节 | 含糊的「检查配置」「重启试试」 |

### 过渡示例

- 「读者收益」→「适用范围」：*掌握上述能力后，请先确认你的环境符合下列要求。*
- 「基本语法」→「选项详解」：*了解语法后，下面按功能域逐一说明各选项。*

## 功能指南模板

适用于功能文档、斜杠命令、插件等「按功能组织」的说明。

```markdown
# [功能名称] 指南

## 引言
<!-- 功能用途、解决的问题、典型用户场景 -->

## 核心概念
<!-- 2–4 个关键概念，各配 1–2 句解释，必要时配图或示意 -->

## 命令层级体系
<!-- 命令树或层级结构（如 /cmd/subcmd），用列表或表格展示 -->

## 快速开始
<!-- 3–5 步完成第一个可用示例 -->

## 配置与选项
<!-- 按模块或用途分组，与工具参考手册的「选项详解」类似 -->

## 典型用法
<!-- 按场景分组，每个场景包含：前置条件、命令、预期结果 -->

## 常见问题与排查
<!-- 同工具参考手册 -->

## 术语表
<!-- 同上 -->
```

### 撰写要点

| 章节 | 包含 | 避免 |
|------|------|------|
| 核心概念 | 领域术语、抽象模型、与上下游的关系 | 直接进入命令细节而无概念铺垫 |
| 命令层级 | 父子关系、必选/可选路径 | 扁平罗列所有命令 |
| 典型用法 | 真实场景、可复现步骤 | 只有命令而无「何时用」「为什么这样用」 |

### 过渡示例

- 「核心概念」→「命令层级」：*理解这些概念后，可以通过以下命令结构进行操作。*
- 「快速开始」→「配置与选项」：*完成快速开始后，如需定制行为，可调整下列配置。*

## 教程模板

适用于分步教程、动手实验、入门指南等。

```markdown
# [教程标题]

## 前置条件
<!-- 所需环境、依赖版本、账号权限，逐条列出 -->

## 目标成果
<!-- 完成后读者将得到什么（产物、能力、可演示结果） -->

## 步骤一：[标题]
<!-- 本步目标 -->
（代码块或操作说明）
<!-- 解释：为何这样做、关键点 -->
<!-- 预期输出：读者应看到的结果 -->

## 步骤二：[标题]
（同上结构）

## 验证方法
<!-- 如何确认目标已达成，可执行的检查命令或操作 -->

## 下一步
<!-- 1–3 个推荐阅读或练习方向，附链接 -->
```

### 撰写要点

| 章节 | 包含 | 避免 |
|------|------|------|
| 前置条件 | 版本号、安装命令、可验证的检查方式 | 模糊的「最新版」「合适的环境」 |
| 每步 | 明确目标、完整代码、预期输出 | 跳步、假设读者已掌握未说明的知识 |
| 验证方法 | 可复制的命令或操作、预期输出示例 | 主观的「看起来正常」 |

### 过渡示例

- 「目标成果」→「步骤一」：*为达成上述目标，首先需要完成以下准备工作。*
- 「步骤 N」→「步骤 N+1」：*完成本步后，输出应包含 X；接下来在此基础上扩展 Y。*
- 「验证方法」→「下一步」：*若验证通过，建议继续学习 [主题] 或尝试 [练习]。*

## 博客文章模板

适用于技术博客、经验分享、案例分析等非正式文档。

```markdown
---
title: [文章标题]
date: YYYY-MM-DD
tags: [标签1, 标签2]
---

<!-- 引言：1–2 段，提出问题或悬念，交代背景与结论概要 -->

## [一级标题：问题/背景]

（正文分层，每节 2–4 段）

## [一级标题：方案/实现]

## [一级标题：结果/反思]

---

*最后更新：YYYY-MM-DD | 适用于 [版本/环境]*
```

### 撰写要点

| 章节 | 包含 | 避免 |
|------|------|------|
| 引言 | 问题或现象、结论概要、阅读收益 | 空泛开场、与正文无关的故事 |
| 正文 | 分层标题、代码/图表、可验证的结论 | 大段文字无小标题、无结构 |
| 脚注式元信息 | 更新日期、适用版本、免责说明 | 用 blockquote 冒充脚注、过度装饰 |

### 过渡示例

- 引言→正文：*要理解这一点，需要先了解 [概念/背景]。*
- 方案→结果：*按上述方式实现后，[指标/现象] 的变化如下。*

## 解释型段落模板

技术文档中，表格、命令、配置项前后需要解释型段落提供信息增量。以下模板可直接复用。

### 表格引导段落

在表格前使用，说明表格的组织方式和阅读重点。

```markdown
以下表格按 [分组维度] 列出 [内容主题]。[列名 A] 列为 [含义]，[列名 B] 列为 [含义]。
如需查找特定 [项目]，可按 [分组维度] 定位到对应区域。
```

示例：

```markdown
以下表格按功能域列出所有 CLI 选项。"选项"列为命令行参数名，"说明"列为该参数的作用。
如需查找特定选项，可按功能域（输入输出、调试、配置）定位到对应区域。
```

### 命令上下文段落

在命令示例前使用，说明为什么运行这条命令、预期结果是什么。

```markdown
[场景说明]。执行以下命令 [目的]：

（代码块）

正常情况下，输出应包含 [预期内容]。如果输出为 [异常内容]，请参考 [排查章节]。
```

示例：

```markdown
确认 Claude Code 已正确安装。执行以下命令查看版本号：

（代码块：claude --version）

正常情况下，输出应包含版本号（如 2.1.0）。如果提示"command not found"，请参考安装章节。
```

### 概念解释段落

在首次引入术语或概念时使用。

```markdown
[术语]（[英文原名]）是 [一句话定义]。在 [上下文] 中，[术语] 的作用是 [具体作用]。
与 [相关概念] 的区别在于：[术语] 侧重 [A]，而 [相关概念] 侧重 [B]。
```

示例：

```markdown
MCP（Model Context Protocol）是一种用于外部工具集成的协议。在 Claude Code 中，
MCP 的作用是让 AI 调用本地或远程的工具服务。与 Skills 的区别在于：MCP 侧重工具
调用协议，而 Skills 侧重预置的知识与工作流。
```

### 版本说明段落

在涉及版本差异的内容前使用。

```markdown
以下内容基于 [产品名] [版本号]。不同版本的 [差异点] 可能有所不同。
核验当前版本：执行 `[核验命令]`，确认输出版本号 ≥ [最低版本]。
```
