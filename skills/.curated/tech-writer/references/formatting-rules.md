# 排版与格式规则

技术文档的排版直接影响可读性和专业度。以下规则适用于面向程序员的中文 Markdown 技术文档。

---

## 中英文排版

| 规则 | Bad | Good |
|------|-----|------|
| 中文与英文之间加半角空格 | `使用Claude Code进行开发` | `使用 Claude Code 进行开发` |
| 中文与数字之间加半角空格 | `共5个参数` | `共 5 个参数` |
| 数字与英文单位之间加空格 | `100MB` | `100 MB` |
| 数字与符号单位之间不加空格 | `100 %` | `100%` |
| 全角标点与其他字符之间不加空格 | `运行 claude ，查看结果` | `运行 claude，查看结果` |
| 专有名词保留原始大小写 | `github、javascript、Macos` | `GitHub、JavaScript、macOS` |
| 完整英文短语不拆分插入空格 | `Model Context Protocol（ MCP ）` | `Model Context Protocol（MCP）` |

---

## 标点符号

### 全角与半角

- 中文语境使用全角标点：，。；：？！（）【】
- 代码上下文、英文引用中使用半角标点
- 同一段落内不混用全角和半角逗号

### 句末与列表

| 场景 | 规则 | 示例 |
|------|------|------|
| 段落结尾 | 用句号 | `会话数据保存在本地磁盘。` |
| 列表项为短语 | 不加标点 | `- 交互模式` |
| 列表项为完整句 | 加句号 | `- 运行 claude --help 查看所有选项。` |
| 表格单元格 | 不加句号 | `通过 ID 恢复历史会话` |

### 破折号禁用

技术文档中禁止使用 `—`（em dash）、`–`（en dash）、`--`（双连字符）作为行文标点。

| Bad | Good |
|-----|------|
| `Claude Code 支持多种模式——交互模式和非交互模式` | `Claude Code 支持多种模式，包括交互模式和非交互模式` |
| `这是一个实验性功能——可能随时移除` | `这是一个实验性功能（可能随时移除）` |
| `MCP 协议 -- 用于外部集成` | `MCP 协议用于外部集成` |

## Markdown 结构

### 标题

- H1（`#`）为文章唯一标题，每篇只用一次
- H2（`##`）起递进，不跳级（H2 下直接用 H4 是错误的）
- 标题不加数字编号前缀（渲染器或 TOC 插件自动处理）
- 标题与正文之间空一行
- 标题使用语义化描述，不用"第一章""第二节"

| Bad | Good |
|-----|------|
| `## 1 引言` | `## 引言` |
| `### 5.1 基础选项` | `### 基础选项` |
| `## 第二章 安装` | `## 安装` |

### 代码块

- 必须标注语言：` ```bash `、` ```json `、` ```typescript `
- 每个代码块前给出上下文说明（为什么运行、预期结果）
- 代码中的占位符用 `<placeholder>` 格式，并在代码块后说明

### 表格

- 表格前必须有引导段落，解释表格的用途和阅读方式
- 表格后可选总结段落，提供信息增量
- 表格不替代正文解释，只做结构化呈现

| Bad | Good |
|-----|------|
| 直接放表格，无前后文 | 先写"以下表格按功能域分组列出所有选项"，再放表格 |
| 表头重复正文内容 | 表格提供结构化视图，正文提供解释和场景 |

## 句子与段落

### 句子长度

- 无标点的短句：不超过 40 字
- 有逗号的长句：不超过 100 字
- 超出时拆分为多个短句

| Bad | Good |
|-----|------|
| `Claude Code 是一个由 Anthropic 开发的命令行工具它支持交互模式和非交互模式可以通过管道接收输入也可以通过选项控制输出格式` | `Claude Code 是 Anthropic 开发的命令行工具。支持交互模式和非交互模式。可通过管道接收输入，也可通过选项控制输出格式。` |

### 段落规则

- 一段一主题
- 段落不超过 7 行，理想长度 4 行以内
- 段落之间空一行

### 语态与表达

| 规则 | Bad | Good |
|------|-----|------|
| 使用主动语态 | `会话数据被保存在本地` | `Claude Code 将会话数据保存在本地` |
| 使用肯定句 | `不是不支持非交互模式` | `支持非交互模式` |
| 避免堆叠形容词 | `强大而灵活的高效智能工具` | `命令行工具` |
| 用事实替代评价 | `这个功能非常好用` | `该功能支持自动补全和历史记录` |
